# Relationship OS 重定位方案

生成时间：2026-04-08  
适用范围：`multi-platform-app` 用户端首页、广场、消息、我的，以及 AI 画像/红娘/恋爱助手/内容工厂的一体化产品重构  
视角：`CEO + Design + Eng`

## 1. 一句话结论

现在的产品形态还是“传统社交内容 app + 一些 AI 功能入口”。

要拉开差异，不能再把 AI 放在功能区、服务宫格、结果页里。要把整个 app 重构成：

**Relationship OS，先理解你，再替你判断，再陪你行动，再帮你表达。**

这不是一个“有 AI 的社交 app”。  
这是一个“围绕亲密关系决策与表达的 agent 产品”。

## 2. 为什么现在这版不够强

### 当前状态

- `首页` 仍以内容分发为主，顶部是内容 tab 切换
- `广场` 仍是典型的帖子/热榜/入口聚合
- `消息` 默认还是通信容器，不是关系工作台
- `我的` 更像账户中心和服务中心，不像“我的模型”
- `AI 画像 / 智能红娘 / 恋爱助手 / 内容工厂` 还没有构成一条用户可感知的主链路

### 用户会怎么理解现在的 app

用户会说：

- 这是个社交 app
- 可以看内容、发帖、聊消息
- 里面有一些 AI 功能

这不够。

我们真正想让用户说的是：

- 这个 app 会先理解我
- 它会告诉我适合认识谁
- 它会告诉我怎么聊、怎么推进
- 它还能替我把内容和表达做出来

## 3. 新定位

### 品牌定位

**AI 驱动的关系操作系统**

### 四层核心能力

1. `Human3.0 / 蒸馏人类`
   用户建模引擎，理解层。
2. `智能画像`
   把理解沉淀成长期可更新的关系模型。
3. `智能红娘 + 智能恋爱助手`
   把模型变成判断、推荐、行动、陪跑。
4. `智能内容工厂`
   把判断和行动外化成资料文案、开场白、内容、案例、表达资产。

### 与别人的差异

- 不是单纯陪伴型 AI 伴侣
- 不是单纯 dating coach
- 不是单纯 AI-native 娱乐 feed
- 不是单纯工具箱

而是：

**画像 -> 推荐 -> 行动 -> 表达 -> 学习回写**

形成闭环。

## 4. 产品北极星

### 用户北极星体验

用户打开 app 后，不是“来刷一下”，而是：

1. 立刻感到“它知道我是谁”
2. 立刻知道“今天它能替我做什么”
3. 立刻有一个低门槛下一步动作
4. 每次使用后，AI 对我的理解更准一点

### 核心指标

- D1 首登画像完成率
- 首页 agent CTA 点击率
- 推荐对象解释卡点击率
- AI 破冰建议采用率
- 恋爱助手侧边栏调用率
- 内容工厂产物发布率/发送率
- 画像二次校准率
- 7 日关系推进任务完成率

## 5. 新信息架构

### 推荐 tab 结构

当前：

```text
首页 | 广场 | 消息 | 我的
```

建议：

```text
月老 | 灵感 | 关系 | 我的模型
```

### 新 IA 的逻辑

- `月老`
  主控台，不是 feed。给判断、推荐、下一步动作。
- `灵感`
  可转化内容场，不是帖子池。所有内容都能 remix 成“适合我”的版本。
- `关系`
  人与人的聊天 + AI sidecar + 风险提醒 + 下一步建议。
- `我的模型`
  用户如何被理解、如何授权、如何校准、如何管理表达资产。

### 页面关系图

```text
                ┌────────────────────┐
                │ 首登关系理解引导    │
                │ Human3.0 蒸馏入口   │
                └─────────┬──────────┘

                          ▼
                ┌────────────────────┐
                │ 我的模型            │
                │ 画像 / 偏好 / 边界  │
                └──────┬───────┬─────┘
                       │       │
          feeds model  │       │ powers control
                       │       │
                       ▼       ▼
              ┌────────────┐  ┌────────────┐
              │ 月老        │  │ 关系        │

              └────┬───────┘  └────┬───────┘
                   │               │
                   └──────┬────────┘
                          ▼
                 ┌───────────────────┐
                 │ 灵感               │
                 │ 内容工厂/案例/表达 │
                 └───────────────────┘
```

## 6. 四个核心页面怎么改

## 6.1 月老页

### 页面使命

让用户一打开 app，就进入“被理解 + 被服务 + 可行动”的状态。

### 第一屏必须回答的 4 个问题

1. 你是谁，我今天如何理解你
2. 我今天替你做了什么判断
3. 你现在最值得做的下一步是什么
4. 为什么是这一步

### 页面结构

```text
┌──────────────────────────────────┐
│ 顶部：月老今天对你的判断           │
│ 标题：慢热认真型，今天适合轻推一步 │
│ 副文案：先从稳定回应的人开始      │
├──────────────────────────────────┤
│ 主动作卡：今天的 1 次有效连接      │
│ CTA: 开始认识 / 让我帮你开场       │
├──────────────────────────────────┤
│ 推荐对象 1/2/3                    │
│ 为什么推荐你                     │
│ 风险提醒                         │
│ 建议开场                         │
├──────────────────────────────────┤
│ AI 已经帮你准备好的 3 件事         │
│ - 优化资料                        │
│ - 破冰建议                        │
│ - 筛掉不合适的人                  │
├──────────────────────────────────┤
│ 继续训练我                        │
│ - 重新校准画像                    │
│ - 更新偏好                        │
│ - 导入更多关系信号                │
└──────────────────────────────────┘
```

### 不该出现的东西

- 传统内容 tab 顶栏
- 多栏目 feed 混排
- 信息过载的卡片瀑布流
- “抖音/同城/圈子” 优先级高于 agent judgement

### 页面状态

| Feature | Loading | Empty | Error | Success | Partial |
|---|---|---|---|---|---|
| 今日判断卡 | 骨架屏 + “月老正在整理今天的判断” | “先完成关系理解引导，我才能开始替你判断” | “今天的判断暂时没拉到，先看上次稳定版本” | 展示今天判断 + CTA | 没有新推荐时展示“继续训练我” |
| 推荐对象 | 3 张 skeleton 卡 | “今天没有足够合适的人，先帮你扩充信号” | “推荐失败，先给你破冰训练” | 3 个推荐对象 + why + action | 只有 1-2 个对象时补足训练/内容模块 |
| 主动作 CTA | disabled + loading 文案 | “先补画像” | toast + 降级路线 | 可直接进入下一步 | 给备用动作，如“先完善资料” |

## 6.2 灵感页

### 页面使命

把内容从“消费品”变成“行动和表达素材”。

### 核心转变

从：

- 最新动态
- 热榜
- 话题广场

变成：

- 可复制的真实案例
- 可改写的开场/表达模板
- 可调用的红娘点评
- 可落到我身上的内容资产

### 页面结构

```text
┌─────────────────────────────────────┐
│ 顶部切换：案例 / 开场 / 表达 / 热议  │
├─────────────────────────────────────┤
│ 今日适合你看的内容主题               │
│ 因为你偏慢热，先看“自然开场”         │
├─────────────────────────────────────┤
│ 内容流                               │
│ 每条内容都有：                       │
│ - 为什么与你相关                     │
│ - 改写成适合我的版本                 │
│ - 用这个去开场                       │
│ - 加到我的资料/表达资产              │
├─────────────────────────────────────┤
│ 内容工厂入口                         │
│ - 生成我的自我介绍                   │
│ - 生成朋友圈 / 帖子 / 话题内容        │
│ - 生成约会计划 / 情绪修复脚本         │
└─────────────────────────────────────┘
```

### 设计原则

- 不做普通帖子流
- 内容卡的主按钮是“拿去用”，不是“点赞评论”
- 每条内容都要解释和用户画像的关系

## 6.3 关系页

### 页面使命

把消息页升级成“关系推进工作台”。

### 页面结构

```text
┌────────────────────────────────────┐
│ 顶部：关系雷达                      │
│ 今天谁值得跟进 / 谁在降温 / 风险提醒 │
├────────────────────────────────────┤
│ 会话列表                            │
│ 每个会话显示：                      │
│ - 当前关系阶段                      │
│ - AI 判断热度                       │
│ - 下一步建议                        │
│ - 风险标签                          │
├────────────────────────────────────┤
│ 会话详情                            │
│ 左侧真人聊天，右侧 AI sidecar        │
│ - 建议回复                          │
│ - 关系推进建议                      │
│ - 不建议说的话                      │
│ - 可一键改写                        │
└────────────────────────────────────┘
```

### 必须强调

- AI sidecar 永远是辅助，不替用户偷偷发送
- 每次建议都要有简短理由
- 风险提醒不能只在失败后出现，要能前置

### 页面使命

```text
│ 我的当前模型                        │
│ archetype + 关键洞察 + 当前节奏     │
├────────────────────────────────────┤
│ AI 如何使用我的信号                 │
│ - 推荐                             │
│ - 红娘                             │
│ - 恋爱助手                         │
│ - 内容工厂                         │
├────────────────────────────────────┤
│ 我的控制权                          │
│ - 公开/私密                        │
│ - 重新校准                         │
│ - 修正理解                         │
│ - 管理边界                         │
├────────────────────────────────────┤
│ 我的表达资产                        │
│ - 资料文案                         │
│ - 破冰模板                         │

```

### 当前已有基础

- `user_onboarding_persona` 已具备轻量关系理解引导
- 资料页与“我的”页已经接入了画像入口
- 这是“我的模型页”的最好起点，不要推翻重来

## 7. 首登链路如何变成主 spine

### 新用户路径

```text
登录
  -> 2分钟关系理解引导
  -> 初始画像结果
  -> 月老首页首屏
  -> 今天的1次有效连接
  -> 关系页 sidecar 陪跑
  -> 灵感页内容工厂补表达
  -> 信号回写画像
```

### 关键原则

- 首登不是“补资料”
- 首登是“Relationship OS 开机校准”
- 校准后马上进入 agent briefing，而不是跳回传统首页

## 8. 三种实现路径

### Approach A: 最小可落地版

- 保持现有 tab 数量不变
- 文案和信息架构重写
- 首页改为 agent briefing first
- 广场改为可转化内容流
- 我的改为模型中心
- 消息页先加 AI 侧边建议，不动底层聊天架构

Effort: M  
Risk: Low  
Pros:
- diff 最小
- 能最快验证“AI 不是功能而是主入口”
- 复用现有路由与服务链路
Cons:
- 关系页仍有旧消息壳子包袱
- 视觉语言会处于过渡态

### Approach B: 推荐方案

- 采用 Approach A
- 同步把消息页升级为“关系工作台”
- 首页/关系/灵感三处统一接同一份画像解释层
- 建立内容 remix -> 资料/聊天/推荐 的统一 action

Effort: L  
Risk: Medium  
Pros:
- 用户能真正感知闭环
- 差异化足够强
- 后续做内容工厂和红娘联动更顺
Cons:
- 需要产品、设计、前端、后端同步改动
- QA 范围明显扩大

### Approach C: 理想版

- 采用 Approach B
- 新增显式 agent orchestration 层
- 建立“关系记忆”和多场景统一 sidecar
- 首页成为月老 agent cockpit
- 内容工厂产物自动进入用户资产系统

Effort: XL  
Risk: High  
Pros:
- 最像真正的 Relationship OS
- 平台潜力最大
- 品牌最清晰
Cons:
- 超出当前一轮重构可控范围
- 工程和验证成本显著上升

### 推荐

**先做 Approach B。**

理由很简单。A 太保守，像换皮。C 太重，容易把团队拖进架构浪漫。  
B 正好，能让用户第一次看懂“这 app 为什么不一样”，又还能用现有基础快速推进。

## 9. 工程拆分建议

## 9.1 复用什么，不要重造

### What already exists

- `user_onboarding_persona`
  轻量画像蒸馏入口，作为 Relationship OS 的开机校准层
- `persona_json`
  已承载 `recommendedOpeningStyle`、`preferredMatchmakerStyle`、`riskFlags`
- 资料编辑页 onboarding 卡片
  可复用为“我的模型”页面中的解释卡
- profile 页面 onboarding 卡片
  可复用为模型中心入口
- 推荐设置页
  可复用为“月老如何替我筛人”的控制面板
- 红娘能力开关和工作台雏形
  可复用为后续“关系工作台”与红娘联动

### 不要做的事

- 不新造第二套正式画像体系
- 不把内容工厂先做成独立 tab 工具箱
- 不做新的复杂 agent runtime 再回头找场景
- 不先做花哨的 feed 重设计而忽略 agent spine

## 9.2 模块拆分

```text
Lane A: 月老首页
  - pages/tab/home.vue
  - related home components
  - persona explain cards

Lane B: 灵感页
  - pages/tab/match.vue
  - content remix actions
  - content factory entry cards

Lane C: 关系页
  - pages/tab/message.vue
  - chat sidecar components
  - risk / next-step widgets

Lane D: 我的模型页
  - pages/tab/profile.vue
  - subpackages/profile/persona-report.vue
  - settings around visibility / recalibration
```

### 并行性

- A、B、D 可先并行
- C 需要消息和助手能力，最好第二波
- 共享依赖是统一的画像解释层和 action schema

## 10. 关键交互定义

## 10.1 首页主 CTA

默认只有一个主动作，不给用户选择困难：

- `开始今天的 1 次有效连接`

次级动作：

- `先让我继续理解你`
- `查看为什么推荐`

## 10.2 所有 AI 推荐都要解释 why

每条推荐对象卡都要有：

- 为什么适合你
- 为什么现在适合联系
- 为什么不建议过快推进

## 10.3 所有内容都要可转化

灵感页每条内容统一四个 action：

- `改成适合我的版本`
- `生成给 TA 的一句话`
- `加入我的资料`
- `交给月老继续用`

## 10.4 聊天 sidecar 的边界

- 不自动代发
- 不伪装成真人
- 不只给模板
- 需要给“理由 + 风险 + 下一步”

## 11. 视觉方向

### 总体方向

不是“社交社区”，是“温暖的关系驾驶舱”。

### 关键词

- 温暖
- 信任
- 关系档案感
- 低噪音
- 有判断力
- 少一点社区感，多一点陪跑感

### 视觉硬规则

- 首页第一屏必须有一个强视觉锚点：`月老今天对你的判断`
- 不允许第一屏出现 generic 信息卡瀑布流
- 不允许上来就是热榜/最新动态
- 不允许“AI 光效 + 卡片网格”套模板
- 卡片只在卡片是交互本体时存在

### 品牌文案方向

- “让月老先理解你”
- “不是多认识人，是认识更对的人”
- “今天这一步，替你少走弯路”
- “我不只陪你聊，我替你判断”

## 12. 交互状态覆盖

| Feature | Loading | Empty | Error | Success | Partial |
|---|---|---|---|---|---|
| 首登引导 | 分步骨架 + 剩余时长预期 | 不适用 | 保存失败时保留已答内容 | 生成画像 + 跳首页 | 草稿保存成功但未确认 |
| 月老推荐 | skeleton + “正在替你筛人” | 没有合适对象时给训练/补信号 CTA | 降级展示旧推荐或训练入口 | 解释型推荐卡 | 只有部分对象时补“继续训练我” |
| 灵感内容 | 分类 skeleton | “今天还没匹配到适合你的灵感” | 展示缓存内容 + 重试 | 可 remix 的内容卡 | 只有案例无模板时提示后补 |
| 关系 sidecar | 侧栏 loading | 暂无建议时显示“先自然聊 2 句，我再判断” | 提示建议失败，不影响真人聊天 | 回复建议 + 风险提醒 | 只有风险无建议时单独展示 |
| 我的模型 | skeleton card | 未生成画像时引导校准 | 回退到上次有效画像 | 模型卡 + 控制权 | 数据部分缺失时显示缺口说明 |

## 13. 风险与失败模式

| Codepath / Feature | Failure Mode | User Sees | 必须处理 |
|---|---|---|---|
| 首登 -> 首页跳转 | 画像已生成但首页没消费 | 用户觉得前面白做了 | 首页必须有首登结果承接 |
| 推荐解释卡 | 只有推荐没有 why | 用户不信任 AI | why 字段必填，缺失时降级不展示 |
| 灵感 remix | 内容可看不可用 | 用户重新把广场当内容流 | 每条内容至少一个“拿去用”动作 |
| 聊天 sidecar | 建议失效或太模板 | 用户认为 AI 很笨 | 保留风险提醒和人工重试 |
| 我的模型控制权 | 用户不知道 AI 用了哪些信号 | 信任下降 | 必须显式说明“AI 如何使用我的信号” |

## 15. 分阶段发布

### Phase 1，2 周内可感知重构

- 首页改成月老 briefing first
- 我的页改成我的模型
- 广场改成灵感页语义
- onboarding 承接串到首页和我的页

### Phase 2，闭环升级

- 关系页 sidecar
- 推荐解释层统一
- 内容 remix 统一 action
